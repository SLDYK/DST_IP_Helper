# 饥荒联机版 IP 联机助手

在 Steam 里开好房间后运行本工具，它会自动把 IP 直连需要的网络环境配好，
并给出一个可以发给朋友的地址。

- **核心逻辑零第三方依赖**，全靠 Python 标准库 ctypes 直调 Win32 API
- **界面用 PyQt6**，也可以直接用打包好的单文件 exe，免装 Python
- **自动识别端口**：直接读系统 UDP 表拿到饥荒真正监听的端口，不猜配置文件
- **自动做端口映射**：自己实现了 UPnP IGD 客户端，自动在路由器上加 UDP 映射
- **自动放行防火墙**：以管理员运行时自动添加入站放行规则
- **能识别双重 NAT**：国内「光猫 + 路由器」两级 NAT 会被准确识别并给出针对性建议
- **能跨 IPv6 联机**：内置纯 UDP 中继，绕过 NAT 把两端缝起来，游戏一个字节都不用改
- **能本机开专用服务器**：直接读已有存档和它启用的模组，一键拉起主世界 + 洞穴，
  不占用游戏客户端，也不用装 steamcmd
- **能接管运行中的服务器**：本机已经有服务器在跑（哪怕是别处启动的）时，
  可以只监控 / 停止，不重复启动
- **可以一键撤销**：加过的规则和映射能完整删掉，不残留、不误删别人的条目

## 安装

### 方式一：直接用 exe（免装 Python）

下载 `饥荒IP联机助手.exe` 双击运行即可，无需安装任何环境。

### 方式二：从源码运行

需要 Python 3.10 或更高版本。

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e .
.venv\Scripts\python.exe main.py
```

> PyQt6 的 wheel 约 80 MB，国内下载可能较慢，可换镜像源：
> `-i https://pypi.tuna.tsinghua.edu.cn/simple`

### 方式三：自己打包单文件 exe

用 **Nuitka** 把 Python 编译成 C 再打包，产物更小、启动更快，也不容易被反编译。

```bat
.venv\Scripts\python.exe -m pip install nuitka ordered-set zstandard
build.bat
```

产物为 `dist\饥荒IP联机助手.exe`（约 20 MB）。

**前置条件：需要一个 C 编译器**，二者任一即可：

| 编译器 | 说明 |
| --- | --- |
| **MSVC**（推荐） | 安装 Visual Studio 时勾选「使用 C++ 的桌面开发」；Nuitka 会自动通过 vswhere 找到 |
| MinGW | 装上 `gcc.exe` 并在 PATH 里，再加 `--mingw64` |

首次编译较慢（约 2~3 分钟，PyQt6 模块多），之后有缓存会快很多。

```bat
build.bat --no-onefile     目录版（启动更快，便于调试）
build.bat --keep-output    保留中间产物，排查编译问题用
build.bat --help           全部选项
```

> 若杀毒软件误报，是单文件自解压引导器的通病；`--no-onefile` 的目录版通常不会被误报。

## 快速开始

1. 先在 Steam 里启动饥荒联机版，创建/进入一个世界（让世界处于运行中）
2. 双击 **`run.bat`**
3. 等它跑完（约 10~20 秒）：中间大字是给朋友的地址，下面一行是控制台直连指令
4. 点「复制指令」把 `c_connect("IP", 端口)` 复制到剪贴板；
   点「复制完整说明」则把加入步骤连地址一起复制，适合直接发给朋友

> 想让它自动配置防火墙，请**以管理员身份运行**。
> 非管理员也能用，只是防火墙那一步会提示需要手动放行。

命令行版本：`run_cli.bat`（支持 `--dry-run`、`--ports`、`--cleanup`）

## 它做了什么

| 步骤 | 说明 |
| --- | --- |
| 1. 找到饥荒进程 | 按可执行文件名 + 路径匹配，兼容不同版本的 exe 名称 |
| 2. 读真实监听端口 | 查 `GetExtendedUdpTable`，挑出绑定在 `0.0.0.0` 且非动态段的端口，即游戏的开房端口 |
| 3. 取本机局域网 IP | `GetIpAddrTable` 枚举所有网卡，默认出口网卡排最前 |
| 4. 查公网出口 IP | 轮询多个国内可达接口；**直连失败才回退到系统代理**，避免把代理出口当成自己的 IP |
| 5. 判断 NAT 类型 | 自己实现 STUN（RFC 5389），用**同一个本地端口**问两台服务器，比较映射端口来区分「稳定映射」和「对称 NAT」 |
| 6. 路由器端口映射 | SSDP 找 IGD → 拉设备描述 → SOAP `AddPortMapping` |
| 7. 探测上游 NAT | 若路由器 WAN 口是私有地址，说明上游还有一层。单播 SSDP + 猜测描述文件路径去找光猫 |
| 8. 放行防火墙 | `netsh advfirewall` 添加入站 UDP 放行规则（仅限本工具命名的规则） |
| 9. 给结论 | 分清「能直连 / 差一步 / 不可能」，并给出具体到 IP 的操作建议 |

界面上会实时显示每一项的检测结果，日志区可以看完整过程。

## 典型场景：双重 NAT

国内家庭宽带最常见的「光猫 + 路由器」两级 NAT 结构，实测输出如下：

```
电脑 192.168.1.100
  └─ 路由器 192.168.1.1（家用无线路由器，UPnP 可用）
        └─ 光猫 192.168.0.1（运营商光猫，UPnP 未开启）
              └─ 公网 203.0.113.10
```

| 项目 | 结果 |
| --- | --- |
| 公网出口 IP | `203.0.113.10`（**有公网 IP，很好**） |
| 局域网 IP | `192.168.1.100` |
| NAT 类型 | 映射稳定（不是对称 NAT，端口映射会生效） |
| 路由器 UPnP | 可用，UDP 10999 / 10998 已自动映射成功 |
| **光猫 UPnP** | **未开启**（SSDP 无响应），工具无法代劳 |
| 结论 | **双重 NAT，还差光猫那一层** |

也就是说：路由器这一半工具已经帮你配好了，剩下的是光猫。
只要在光猫上再补一步，朋友就能直接连。

## 怎么解决「双重 NAT」

在浏览器打开 **<http://192.168.0.1>**，用光猫背面的账号登录
（要改 DMZ / 端口映射通常需要「超级管理员」账号，普通账号可能看不到这些选项；
如果登录后找不到对应菜单项，可以打运营商客服或在网上查询该型号的「超级密码」，
也可以直接让装维师傅帮你设置）。

三种改法，按省事程度排序：

### 方案 A：光猫设置 DMZ（推荐，最省事）

在光猫里找到 **DMZ / 军事区 / 非军事区**，把 DMZ 主机设为 **`192.168.0.2`**
（这是路由器的 WAN 地址）。

设好之后，本工具加的路由器端口映射就能一路通到公网，**之后每次开黑只要跑一次 `run.bat` 就行**。

> 代价：DMZ 会让路由器完全暴露在公网上。若在意安全，改用方案 B。

### 方案 B：光猫上做端口映射

在光猫里找到 **端口映射 / 虚拟服务器 / NAT 转发**，添加：

| 外部端口 | 协议 | 内部 IP | 内部端口 |
| --- | --- | --- | --- |
| 10999 | UDP | `192.168.0.2` | 10999 |
| 10998 | UDP | `192.168.0.2` | 10998 |

（第二个端口只有开了洞穴才需要）

### 方案 C：光猫改桥接（彻底解决）

把光猫改成**桥接模式**，由路由器 PPPoE 拨号。这样只剩一层 NAT，
本工具的 UPnP 映射直接生效，以后再也不用管光猫。

需要在光猫里改成桥接、并在路由器里填宽带账号密码，改完可能要重启光猫。
同样需要超级管理员权限，建议让装维师傅来做。

### 另外可以试试

在光猫设置里找 **UPnP** 开关并打开。如果打开后有响应，
本工具下次运行就能**全自动**把两层 NAT 都打通，完全不用手动配置。

## 另一条路：UDP 中继（跨 IPv6 / 完全不用动光猫）

上面那套是「把 NAT 打通」。如果打不通（没有光猫超管权限、宽带是 CGNAT、
或者有一方**只有 IPv6**），还有一条更直接的路：**不打通，绕过去**。

做法是在两端各跑一个「双向 UDP 转发器」，把包原样搬运，不解析游戏协议。
图形界面的「**UDP 中继**」标签页里就能操作，也可以用命令行 `run_relay.bat`。

```
┌─ 主机侧（你的电脑，有公网 IPv6）─────────────┐
│  DST 服务器   0.0.0.0:10999                   │
│       ↕ 本机回环（每位朋友一个 127.0.0.x）     │
│  中继 listen  [::]:20000                      │
└────────────── ↕ 公网 IPv6 ───────────────────┘
┌─ 朋友侧（只有 IPv4）─────────────────────────┐
│  中继 listen  127.0.0.1:10999                 │
│       ↕ 本机回环                              │
│  DST 客户端   c_connect("127.0.0.1", 10999)  │
└───────────────────────────────────────────────┘
```

**为什么这样能行**：双方都以为自己在跟本机进程说话。`127.0.0.1:10999` 由中继接管，
朋友连它就像连局域网服主；两个中继之间走 IPv6，没有 NAT 也就没有端口映射问题。
**游戏本身对此一无所知**，所以不需要改游戏，也不需要装 mod。

### 用图形界面（推荐）：联机码

切到「**UDP 中继**」标签页，全程**不用手敲 IP 和端口**，只交换两段码：

1. **第 1 / 2 步**：程序自动检测本机能不能中继（需要有全局 IPv6），
   然后选自己的角色——**主机**（我开世界，别人连我）或**加入方**（我连别人的世界）
2. **主机**：第 3 步会出现一段 **`HOST…` 主机码** → 点「复制主机码」发给朋友
3. **加入方**：把收到的 `HOST…` 粘进第 3 步 → 第 4 步**立刻生成**自己的
   **`JOIN…` 加入码** → 点「复制加入码」发回给主机
4. **主机**：把 `JOIN…` 粘进第 4 步的「管理加入码」（可填备注标记是谁）→
   点「**确认生效并启动中继**」。加入码里的地址会被自动配进白名单，
   防火墙必要时也会自动放行
5. **加入方**：等主机说一声好了，点第 5 步「**启动中继**」→ 窗口直接给出
   `c_connect("127.0.0.1", 10999)` 指令 → 点「复制指令」→ 进游戏按 <kbd>`</kbd> 打开控制台粘贴执行

主机码里**已经带上了端口映射和校验值**。加入方的地址由加入码写进白名单，
而**只有从这份主机码派生出来的加入码才放得进来**，陌生人就算知道你的公网地址也会被拒。
加入码会记住，下次不用重新交换。

> 主机点「重新生成」等于换一把锁——**之前发出去的加入码会全部作废**。

### 用命令行

#### 主机侧（你）

先看看自己有没有公网 IPv6：

```
run_relay.bat --show-address
```

把打印出来的**全局 IPv6** 那一行记下来（要发给朋友），然后启动中继：

```
run_relay.bat --auto-ports --auto-base 20000 --allow 2409:8a60::/32
```

- `--auto-ports` 直接读系统 UDP 表拿到饥荒真实监听的端口（**先开好世界再跑**），
  每个端口自动配一条规则，从 `20000` 开始编号
- `--allow` 是白名单，**强烈建议填**：中继监听在公网 IPv6 上，
  不限制的话谁扫到都能蹭

启动后除了规则表，还会打印**朋友侧该怎么配**，直接复制给 TA。

### 朋友侧

```
run_relay.bat --map 127.0.0.1:10999=[<你的IPv6>]:20000
```

然后朋友在饥荒里照常连 **`127.0.0.1:10999`** 就行了。

### 如果包进不来

中继本身不需要管理员权限，但 **Windows 防火墙默认拦入站 UDP**。
用管理员运行一次下面的命令放行即可：

```
netsh advfirewall firewall add rule name=DST-Relay-20000 dir=in action=allow protocol=UDP localport=20000
```

### 有什么特点

| 能力 | 说明 |
| --- | --- |
| 纯转发 | 一个字节都不改，所以它也不认识饥荒，能中继任何 UDP 游戏 |
| 一人一个套接字 | 主机侧还给每位朋友分配独立的 `127.0.0.x` 回环地址，游戏眼里像局域网里的几台机器 |
| 自动识别端口 | 复用主程序的 UDP 表探测，不用手填端口 |
| 白名单 | `--allow` 支持地址或 CIDR，防止陌生人蹭连接 |
| 自动清理 | 空闲 peer 自动回收，peer 表不会无限增长 |
| 跨平台 | 只用标准库 socket，Linux / macOS 也能跑（只有「自动识别端口」是 Windows 专属） |

## 第三条路：本机开专用服务器（不用游戏客户端开房）

前两条路都是「你已经在游戏里开好房」。如果你想要一个**不依赖游戏客户端、
可以一直挂着**的服务器，用「**开服**」标签页直接从本机已有存档拉起来。

几个可能反直觉的事实：

- **不需要装 appid 343050，也不需要 steamcmd**。
  专用服务器程序（`dontstarve_dedicated_server_nullrenderer_x64.exe`）
  **就是游戏本体自带的**，在 `bin64\` 下
- **不需要开着 Steam 客户端**。它以 SteamGameServer 身份用 `steam_api64.dll` 登录
- **需要 Klei 开服令牌**。没有令牌服务器会打印 `!!!! Your Server Will Not Start !!!!`
  直接退出，这是 Klei 的硬性要求

### 拿令牌

在 `accounts.klei.com/account/game/servers` 登录后走 **Generate Server Config Files**，
从下载到的压缩包里取出 `cluster_token.txt`。

> 游戏 EXE 里还留了另一条官方说明：在**已登录**的客户端里按 <kbd>`</kbd> 打开控制台，
> 执行 `TheNet:GenerateClusterToken()`，令牌会生成在客户端设置目录。
> 实测这条**不稳定**（有时不生成任何文件），拿不到就走上面官网的路。

### 用图形界面

切到「**开服**」标签页：

1. **第 1 步 · 选择一个存档**：自动扫描 `文档\Klei\DoNotStarveTogether\<账号>\Cluster_N`
   （稳定版和 Beta 分支的存档都能扫到，各自用各自的 `-conf_dir`）。
   选中后会显示存档摘要和**它启用的全部模组**（名字取自各 mod 的 `modinfo.lua`）
2. 如果这个存档**缺令牌**，会多出一行粘贴框——把令牌粘进去点「保存令牌」即可
   （写入前会先备份已有的 `cluster_token.txt`）
3. 勾选是否要「启动前更新模组」（连 Steam，较慢；不勾则跳过，启动更快）
4. **第 2 步 · 启动专用服务器**：先起主世界，等它就绪再起洞穴。
   右边是实时服务器日志。关窗口时如果服务器还在跑，会问你是**停止并退出**还是
   **只退出**（服务器继续跑，下次可以接管回来）

两个按钮值得注意：

| 按钮 | 用途 |
| --- | --- |
| 接管运行中的服务器 | 本机**已经有**服务器在跑时（哪怕不是本工具启动的），只接管监控 / 停止，不重复启动 |
| 停止服务器 | 停止本工具启动的，或已接管的外部服务器 |

找不到游戏 / 存档时展开「**高级设置**」，可以手动指定游戏目录、存档根目录、
`conf_dir` 和附加参数（都会记住）。

### 用命令行

```
run_cli.bat --list-clusters                      列出本机所有存档（名称 / 端口 / 模组数）
run_cli.bat --start-server Cluster_2             拉起这个存档，Ctrl+C 停止
run_cli.bat --start-server Cluster_2 --update-mods  启动前先更新模组
run_cli.bat --attach                             接管正在运行的服务器（只监控，Ctrl+C 脱离）
run_cli.bat --stop-server                        停止正在运行的服务器（含外部启动的）
run_cli.bat --set-token Cluster_2                把令牌写进这个存档（回车后粘贴令牌）
run_cli.bat --set-paths --game-dir "D:\DST"      手动指定路径并保存
```

### 会踩的坑（工具都已经处理）

- **就绪判定读的是服务器进程的 stdout，不是 `server_log.txt`**。日志文件是缓冲的，
  启动早期永远看不到「就绪」那行，曾经因此假卡死两分钟
- **必须传 `-sigprefix`**。IPC 就绪信号名是 `<sigprefix>_Ready`，不传的话信号名不可预测——
  服务器其实已经在监听端口了，但就绪信号永远不出现
- **局域网集群（`lan_only_cluster = true`）默认加 `-offline`**。这类存档带云存档 ID，
  在线启动会去敲 Klei 的接口，在网络不好的时候会无限重试卡死在启动阶段

## 朋友怎么加入

把工具给出的地址发给朋友，让 TA 在饥荒联机版里：

1. 主菜单 → **加入游戏**
2. 在服务器列表的**搜索框**里输入 `IP:端口`（例如 `203.0.113.10:10999`）后回车
   - 不同版本的入口位置略有差异，如果搜索框不生效，试下一种
3. 备用方法：主菜单按 <kbd>`</kbd> 键打开控制台，输入
   `c_connect("203.0.113.10", 10999)`

> 同一个 WiFi 下的朋友就不用折腾这些了，直接用 **`192.168.1.100:10999`** 连，
> 局域网内不走公网，跟防火墙和端口映射都没关系。

## 命令行用法

```
run_cli.bat                     完整检测并自动配置，最后打印可分享的说明
run_cli.bat --dry-run           只检测，不改动防火墙和 UPnP
run_cli.bat --ports 10999,10998 手动指定端口（默认自动识别）
run_cli.bat --cleanup           删除本工具添加的防火墙规则和 UPnP 映射
run_cli.bat --y --cleanup       撤销时不询问
```

开专用服务器（见「第三条路」一节）：

```
run_cli.bat --list-clusters                     列出本机所有存档
run_cli.bat --start-server Cluster_2            拉起这个存档（主世界 + 洞穴）
run_cli.bat --attach                            接管正在运行的服务器
run_cli.bat --stop-server                       停止正在运行的服务器
```

UDP 中继（跨 IPv6 / 绕 NAT，见上一节）：

```
run_relay.bat --show-address                       看本机 IPv4 / IPv6 地址
run_relay.bat --auto-ports --auto-base 20000       主机侧：自动识别端口并开中继
run_relay.bat --map "[::]:20000=127.0.0.1:10999"   主机侧：手工指定规则
run_relay.bat --map 127.0.0.1:10999=[2001:db8::1]:20000   朋友侧
run_relay.bat --help                               全部选项
```

也可以直接当模块调：`python -m dst_ip_join.relay --help`

## 自检与排错

```
python selftest.py
```

会逐项验证（本机约 110 项，视环境跳过若干），包括几个容易静默出错的地方：

- `GetExtendedUdpTable` 的**网络字节序换算**（端口/地址）
- 64 位下**句柄是否被截断**（否则拿到的进程路径是空的）
- STUN 响应的 XOR-MAPPED-ADDRESS 解码
- CGNAT 网段边界判断
- 剪贴板读写、界面能否正常构建
- 中继能否把字节**原样**搬运（起两条中继串起来跑一遍真实收发）
- 中继能否给每位朋友分配**不同的回环地址**
- 联机码往返编码、加入码白名单过滤、双端中继真包转发
- 主世界端口必须是 10999 而非 `min(端口)`（`min()` 会选到洞穴分片）
- 存档扫描、模组解析、命令行参数解析（含 `APP:Klei/` 这种别名）、
  日志增量读取、无匹配存档时的降级接管

> 用 `.venv` 里的解释器跑会有 1 项失败（`QueryFullProcessImageNameW` 拿到的是
> 基础解释器路径而不是 venv 的），这是 venv 启动器的特性、不是缺陷；
> 用系统装的 Python 直接跑是 0 失败。

排查光猫/路由器开了哪些服务：

```
python probe_host.py 192.168.1.1
```

## 已知限制

- **只支持 Windows**（依赖 Win32 API：UDP 表、netsh 防火墙、剪贴板）
- **需要开房后运行**：端口靠读取饥荒进程的 UDP 监听来识别，
  没开房时会退回默认端口 10999 / 10998
- **运营商级 NAT 无解**：如果公网出口本身是 `100.64.0.0/10`，
  端口映射不可能生效，只能申请公网 IP 或改用内网穿透 / 虚拟局域网
- **光猫 UPnP 关闭时无法自动打通**：这是设备侧的限制，只能手动配置
- UPnP 映射在路由器/光猫重启后可能失效，重新运行一次本工具即可
- 若系统装了全局代理，公网 IP 查询会先尝试直连；万一只有代理能出网，
  结果会标注「经过代理」，此时的 IP 可能不是你的真实公网地址

中继的额外限制：

- **必须双方各跑一个**。游戏是 P2P 直连，只改一边没有任何意义
- **主机侧中继暴露在公网**。请务必用 `--allow` 限制来源，否则谁扫到都能连
- **游戏内看到的玩家地址都是回环地址**（`127.0.0.x`）。正常游戏不受影响，
  但如果有 mod 按 IP 做限制或封禁，会不符合预期
- 主机侧给朋友分配的是 `127.0.0.2` 起的回环地址，**上限 253 位朋友**（够用）
- 「本机自己连自己」的测试会走系统内部回环优化，**不能证明外部真能进得来**；
  最终还是要找一个真正的第三方朋友试一次
- 中继是明文转发，本身不加密。需要保密就在两端套一层 VPN（Tailscale 之类）

开服（专用服务器）的额外限制：

- **同一份存档不能被游戏客户端和专用服务器同时占用**
- **同一个令牌也不建议同时跑两个存档**，Klei 那边可能判成异常
- 令牌是账号级凭证，**不要连同存档一起打包发人**（本工具只写入、不会外传）
- 停服务器用的是 `taskkill /T /F`，**不会等它正常存档退出**。
  想保险就在游戏里先让所有人离开世界（服务器会自动存盘）再停
- 接管外部服务器时**只监控日志文件**（拿不到进程 stdout），
  所以日志是「从接管那一刻起」的新增内容
